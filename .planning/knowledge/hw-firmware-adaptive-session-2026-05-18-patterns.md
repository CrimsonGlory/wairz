## Successful Patterns

### 1. Pre-implementation parallel scout dispatch with per-claim source verification
- **Description:** Before writing TARGET 2 (Realtek BT parser) + TARGET 3 (Tegra/L4T + recursive unpack), launched 3 parallel Citadel research scouts (A: Tegra structure, B: recursive-unpack heuristics, C: Realtek corpus). Scout C cross-referenced the user-prompt's claim that Realtek project_id sits at offset 8 — discovered upstream `drivers/bluetooth/btrtl.h` actually places `fw_version` there; project_id is in trailing TLV records reverse-scanned from file tail. Implementing the prompt verbatim would have shipped a parser that misclassified every Realtek blob.
- **Evidence:** Commit `5f40eb2` cites Scout C's correction; the parser's `_scan_realtek_project_id_from_tail` implements the tail-TLV scan; 42 tests round-trip 6 chipset variants. Cost ~5 min via parallel scout dispatch; value: parser-shape correction that prevented wholesale misclassification.
- **Applies when:** Any session that begins from a prompt + spec claim that names byte offsets, magic bytes, file structure, or protocol fields. Per-claim source verification (upstream kernel for kernel-driver formats; vendor docs for vendor-specific formats; RFC for protocol formats) catches design errors at near-zero cost. Extends 2026-05-17 Pattern #3 (reviewer-claim verification via web-fetch) to the prompt-claim case.

### 2. Multi-persona reviewer dispatch (3 parallel) catches structurally different bug classes
- **Description:** After all 4 feature commits shipped, dispatched 3 parallel Citadel reviewers (A: architecture, B: forensic-domain, C: adaptability). Each axis caught different findings: Reviewer A surfaced a pre-existing JSONB clobber bug + module-location architectural issue; Reviewer B surfaced a CVE-attribution schema gate gap + a Scout-A-derived NVD-CPE misattribution; Reviewer C surfaced a subdirectory-probing gap + vendor proactive-seed gap. Total: 2 CRITICAL + 4 HIGH + 18 MEDIUM + 15 LOW findings across 3 reviewers. Single-thread review would have missed structurally orthogonal issues — each reviewer's lens informs different findings.
- **Evidence:** Commits `7730915` (Reviewer A + C HIGH findings applied — 5 fixes) + `51db3c8` (Reviewer B CRITICAL + HIGH findings applied — 2 fixes + 4 paired-canary tests). Three consecutive sessions now (2026-05-15..18) have shipped CVE-attribution failure modes that the multi-persona pattern caught — durable beyond debate.
- **Applies when:** Any session shipping classifier + matcher + attribution changes. Cost: 3 parallel Citadel agent dispatches (~5-10 min wall clock). Value: catches structural bug classes that one-axis review misses (architecture vs forensic vs adaptability are intentionally orthogonal lenses).

### 4. Bytes-weighted + sidecar-aware + negative-rootfs-guarded adaptability gate
- **Description:** `_is_archive_dense_layout(path)` in unpack_common.py uses bytes-weighted (not count-weighted) archive-fraction + sidecar-exclusion (.md5/.sha256/.sig/etc) + negative-rootfs guard (≥2 of bin/etc/usr/lib/system markers short-circuits). DS1's 6-file layout was 33% archive BY COUNT (2 archives + 4 sidecars) but ~100% archive BY BYTES (sidecars were ~600 bytes against 2.5 GB of archive). Bytes-weighted with sidecar exclusion catches DS1; count-weighted alternative would have missed it silently. Plus a subdir-depth-1 probe via `_probe_subdirs_for_archive_density` when top-level fails but ≤8 subdirs exist — captures vendor-wrapper conventions like `payloads/`.
- **Evidence:** Commits `e2f8333` + `7730915`. 13 tests in `test_nested_extract_gate.py` cover 5 fixtures + Rule #46 paired canaries. End-to-end validated against the live DS1 firmware: gate fires correctly + recursion exposes 124 firmware-like files (was 6).
- **Applies when:** Any heuristic gate that decides between "treat as already-resolved" vs "recurse further". The discipline: byte-weighting beats count-weighting when sizes vary by orders of magnitude; sidecar exclusion is mechanical; negative-rootfs guards short-circuit cleanly for the canonical case. Avoids the "hard-code vendor allowlist" antipattern by making the gate generic + adaptive.

### 5. Confidence ladder (HIGH/MEDIUM/LOW) preserves operator value at all evidence levels
- **Description:** The Realtek BT parser emits HIGH on canonical magic + project_id in YAML; MEDIUM on magic-at-non-zero-offset OR project_id outside YAML; LOW on soft `[Rr]ealte[ck]` ASCII fallback. Rather than failing closed (parser returns None on partial evidence), operator-modified blobs surface with a confidence label so the UI + CVE matcher can act on evidence quality.
- **Evidence:** Commit `5f40eb2` parser code at `_parse_realtek_bt`; 42 tests verify each confidence tier. Mirrors the bt_firmware_banner.py precedent for QCA/Broadcom/MediaTek. The Tegra classifier patterns commit (`3000a9e`) uses the same confidence shape: HIGH for canonical filenames, MEDIUM for vendor-customised (ds1-*.img).
- **Applies when:** Any classifier / parser that operates on potentially-vendor-modified inputs. The discipline avoids "all-or-nothing" classification + lets downstream consumers (matchers, UI, CVE attribution) make their own confidence-floor decisions.

### 6. YAML hot-reload "keep previous on malformed" makes operator iteration painless
- **Description:** The `MtimeCachedYamlLoader.get()` keeps the PREVIOUS valid cached state when a reload fails (parse error, structural validation error). It does NOT silently regress to in-tree defaults. The mtime cursor advances past the malformed file so subsequent retries only happen when the operator saves again (avoiding a retry storm). WARN log surfaces the failure for shell-equipped operators.
- **Evidence:** Commit `c7a6106` `_yaml_cache.py` `_reload()` method. Live demonstration during session: an invalid YAML mutation triggered the WARN + kept previous state; restoration cleanly returned to the original 5 codenames. The "test_malformed_reload_keeps_previous_valid_state" test in `test_yaml_hot_reload.py` is the Rule #46 paired canary.
- **Applies when:** Any cache-on-write data file that operators iterate on. The contract is the antithesis of "fail-closed to defaults" — production state is preserved through transient typo cycles. Pairs with the success-path INFO logs ("loaded — N entries (YAML, not defaults)" + "reloaded due to mtime change") for full operator visibility.

### 7. Schema gates against disclosure-batch antipatterns (defense at TWO layers)
- **Description:** F-FORENSIC-10 (Reviewer B) added a schema-time rejection of `bt_banner_cve_pins.yaml` entries with `family: <X>` set AND no other narrowing condition. The matcher tier in cve_matcher.py already requires per-CVE chipset_regex narrowing; the schema gate prevents the YAML from ACCEPTING the antipattern shape in the first place. Two complementary layers: at-load (schema), at-match (matcher fields).
- **Evidence:** Commit `51db3c8` patterns_loader.py `_parse_banner_cve_pin` raises ValueError on family-only pins; 2 paired-canary tests verify the gate fires + the negative-canary (family + chipset_target_in IS accepted). The discipline prevents future operators from re-shipping the BTFM/BrakTooth attribution antipatterns at the source.
- **Applies when:** Any schema accepting operator-authored attribution rules. When the antipattern is mechanically describable (in this case: "family: set alone is insufficient narrowing"), the schema layer is the right place to enforce — louder than runtime + earlier in the operator's edit-test cycle.

### 8. Confidence floor on curated CVE matcher (F-FORENSIC-11)
- **Description:** `_match_curated` in cve_matcher.py now skips blobs with `detection_confidence == "low"`. A LOW-confidence vendor=realtek blob (e.g. from the Realtek BT parser's soft-fallback ASCII match against any "Realtek" copyright string) would have inherited curated Realtek CVE attribution. The confidence floor gates curated-tier attribution on the QUALITY of the vendor evidence, not just the vendor label.
- **Evidence:** Commit `51db3c8` cve_matcher.py `_match_curated` early-return; 2 paired-canary tests in `test_hardware_firmware_cve_matcher.py` verify the gate fires on low-confidence AND the negative-canary (medium-confidence still triggers). Complements F-FORENSIC-10 — F-FORENSIC-11 gates BLOB EVIDENCE quality; F-FORENSIC-10 gates PIN AUTHOR-INTENT quality.
- **Applies when:** Any CVE attribution layer that consumes a confidence-laddered classification. Soft-evidence vendor matches should NOT pollute curated CVE rows. The discipline complements F-FORENSIC-10 at the runtime side.

### 9. Cross-vendor architecture: generic primitives belong in app/utils/, not domain subpackages
- **Description:** The `MtimeCachedYamlLoader[T]` class shipped initially at `backend/app/services/hardware_firmware/_yaml_cache.py`. Reviewer A surfaced that the class is generic over T + already imported by `cve_matcher.py` via cross-subpackage path. Moving to `backend/app/utils/yaml_cache.py` (mirroring `sandbox.py` / `truncation.py` / `pagination.py` siblings) signals correct scope + invites future codebase-wide adoption. The user's "we won't be the only ones ingesting" framing predicts this primitive will see many consumers; placing it under hw-firmware/ would have artificially constrained its visibility.
- **Evidence:** Commit `7730915` moved the file via `git mv`; 3 importers updated cleanly; 348 tests pass post-migration.
- **Applies when:** Any new utility class authored inside a domain subpackage. If the class is generic (parameterised by T, or domain-agnostic in its logic), it belongs in `app/utils/` or equivalent codebase-wide layer.

### 10. Reviewer-claim verification via NVD web-fetch extends to Scout-claim verification
- **Description:** Scout A's research report on Tegra/L4T included a citation that CVE-2019-5680 (Selfblow) applied to L4T R32.3.1 + DS1's build was "8 days before JetPack 4.3 release". Reviewer B fetched the NVD page for CVE-2019-5680 directly + discovered: CPE caps at R32.2 (so R32.3.1 is the FIRST FIXED version), and the CPE list is TX1-only (DS1 is TX2). If a future curated `vendor: nvidia` YAML entry shipped CVE-2019-5680 per Scout A's recommendation, every R32.3.1+ Tegra firmware would have received false-positive Selfblow attribution.
- **Evidence:** Reviewer B's F-FORENSIC-03 finding cited the direct NVD URL; the postmortem's "What Broke" #9 documents the catch. Pattern #3 from 2026-05-17 ("independent reviewer-claim verification via web-fetch") now extends to scout reports — the discipline applies recursively across the research-to-curation pipeline.
- **Applies when:** ANY claim about CVE attribution — whether from a scout, a reviewer, a user prompt, a vendor advisory, or an LLM summary. The NVD per-CVE CPE fetch is the authoritative source; everything else is a candidate-finding to verify against it.

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Hot-reload contract: KEEP PREVIOUS on malformed (NOT regress to defaults) | Operators editing YAML in a text editor get transient invalid states between save cycles — defaulting on every transient is hostile UX. Previous valid state is much better fallback than in-tree defaults. | Worked. Live demo: invalid YAML triggered WARN + kept previous; restored cleanly. Mtime cursor advance prevents retry storm. |
| Bytes-weighted (not count-weighted) archive density | DS1's 33%-by-count was 100%-by-bytes. Count-weighted alternative would have missed every "2 archives + N sidecars" vendor-wrapper shape. | Worked. Gate fires on DS1 + 4 synthetic fixtures; doesn't fire on flat rootfs (negative-rootfs guard). |
| 1 MB min_archive_size threshold (down from 10 MB) | 10 MB was right-sized for Tegra/Samsung-scale packages but biased against IoT/embedded firmware (ESP32 packages 4-8 MB; Nordic SoftDevice ~1.5 MB). 1 MB still suppresses stray-tarball-in-config-dir false-fires. | Worked. Reviewer A finding addressed; existing tests still pass with the lower threshold. |
| Subdirectory probing at depth-1 for sparse top-levels | Vendors wrap archives in `payloads/` / `images/` subdirs; top-level-only gate misses these. Bounded to ≤8 subdirs to prevent adversarial blowup. | Worked. Reviewer C REC-1 addressed; bounded-cost probe keeps the gate fast. |
| Realtek parser: dual head+tail scan mirroring QCA Rome | Upstream btrtl.c uses tail-TLV scan for project_id. Same pattern wairz already runs for QCA BTFM. Reusing the existing dual-window infrastructure (4 KB head + 8 KB tail) is zero new I/O cost. | Worked. 42 tests; live smoke against 6 chipset variants. |
| Soft-fallback regex `[Rr]ealte[ck]` accepts both "Realtek" and "Realtech" + case variants | btrtl.c's canonical magic is "Realtech" (typo'd by Realtek decades ago). Vendor-modified blobs may use the brand-correct "Realtek". Soft regex captures both — LOW confidence flags the absence of canonical evidence. | Worked. Soft-fallback fires on 6 case-variant fixtures; downstream confidence floor (F-FORENSIC-11) prevents low-confidence pollution. |
| family-only CVE pin rejected at SCHEMA layer | The disclosure-batch antipattern has hit wairz 3 sessions in a row (2026-05-15..17). Schema-layer rejection is louder + earlier than runtime-layer rejection. Operators iterate at the YAML; the error surfaces during their save cycle. | Worked. Pre-existing in-tree pin (qualcomm-braktooth-...) has family + chipset_target_in, so passes. New paired-canary tests verify both directions. |
| `_yaml_cache.py` moved from `hardware_firmware/` to `app/utils/` | The class is generic; downstream consumers across the codebase will adopt. Module location signals scope; subpackage-internal placement artificially constrained adoption. | Worked. 3 importers updated; 348 tests pass post-rename. |
| 28 proactive vendor display strings (up from 4) | firmware_patterns.yaml already names 20+ vendor prefixes; operator uploads from Allwinner/Rockchip/Marvell/etc would surface as title-cased fallbacks otherwise. Display strings only — zero behaviour change. | Worked. Live smoke confirms display map covers the new entries. |
| Defer Tegra CVE pins to follow-up commit with per-NVD-CPE verification | Scout A's research listed CVEs as future-pinning candidates; Reviewer B's per-NVD-CPE check revealed multiple errors (CVE-2019-5680 already FIXED in R32.3.1; CVE-2022-42270 Xavier-only; CVE-2021-34397 chipset-specific). Shipping CVE pins this session would replicate the prior-session antipattern. | Worked. Postmortem's "Recommendations Carried Forward" #3 documents the per-CVE chipset/version narrowing recipe. |
